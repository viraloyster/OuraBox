# OuraBox documentation

These documents are the foundation of the project. Before writing code or designing screens, this is where we define **what OuraBox is, what it believes in and how it speaks**. Any product decision should be justifiable by what is here; if something contradicts it, it gets discussed and one of the two things changes.

They are living documents: they change as the idea matures.

## Contents

1. [Vision](01-vision.md): where OuraBox comes from, who it's for and how far it wants to go.
2. [Philosophy](02-philosophy.md): the principles that are not negotiable.
3. [The voice](03-voice.md): how OuraBox speaks, with an example and a counterexample.
4. [The three spaces](04-spaces.md): safe space, community and companies.
5. [Lessons](05-lessons.md): what happened to others who tried something similar.
6. [Open questions](06-open-questions.md): what is still unresolved.
7. [Technology](07-technology.md): how it's built, derived from the philosophy: security and optimization.
8. [Plan](08-plan.md): the stages, in order, with their exit criteria.
9. [The safe space](09-safe-space.md): what a person does on their PC with OuraBox.
10. [Design](10-design.md): how it looks and how it feels.
11. [Economic model](11-economic-model.md): how it sustains itself, without charging users.
12. [Architecture](12-architecture.md): how the app is built inside and what it guarantees.

The future stages each have their TODO document in [`stages/`](stages/).
